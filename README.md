# Bricksplaza

South African e-commerce storefront for bricks, pavers, blocks and related masonry.

Product pages read the `products` table. The generated SKU list has been removed from the shop. `node scripts/seed-products.mjs` only reports how many rows are already loaded. Accounts, carts, orders and reviews use Postgres (PGLite in local preview when `DATABASE_URL` is unset, Supabase when it is set). Do not commit secrets or connection strings.

## Render

The production build is a Node server for [Render](https://render.com/docs/infrastructure-as-code), not Vercel. `render.yaml` is the Blueprint. It does not create a database.

1. Push `main`. In Render: New → Blueprint → this repository. If a service already exists from an older blueprint, open it and set the build and start commands below, then clear the build cache and redeploy.
2. Build command: `npm ci --include=dev && npm run build`
3. Start command: `node scripts/render-start.mjs`
4. Set `DATABASE_URL` to the Supabase **session pooler** URI (`pooler.supabase.com`). The direct `db.<project>.supabase.co` host will not deploy.
5. `BETTER_AUTH_SECRET` is generated by the blueprint. Add `COMPANY_VAT_NUMBER` later if you want it on the tax invoice. Set `BETTER_AUTH_URL` only when you attach a custom domain.

`npm run build` only compiles. Migrations run on boot, then the process listens on `PORT`. The health check is `GET /healthz`. Card capture stays off.
